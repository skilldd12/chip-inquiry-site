# 首屏动态分镜

实现文件：`components/hero/hero-stage.tsx`（动效）+ `app/globals.css`（`.hero__*`）。
以下数值均为代码中的真实值，不是示意。

## 0. 三个状态与素材

| 状态 | 画面 | 素材 | 传达 |
| --- | --- | --- | --- |
| 01 整体 | QFP 封装的三分之四视角，占满视口，文字压在左下留白 | `public/images/hero-state-01.jpg` | 「我们在做的是这些器件」 |
| 02 微距 | 引脚阵列微距，金属反光沿引脚走 | `hero-state-02.jpg` | 「关心的是引脚、间距、批次」 |
| 03 俯视 | 多颗元件平面排列，视线拉回整体 | `hero-state-03.jpg` | 「不是单颗，是配单」 |

右侧仪表栏固定显示 `INDEX 01/03` 与三行读数（`RENDER / FORMAT / BRANDS`）。`RENDER` 一栏写的是 **PRE-BAKED 2.5D**——三张预烘焙静帧 + 相机式位移，**不是 3D 渲染、不是实拍转场**，页面上也照此标注。

## 1. 入场（0 – 2.2 s）

| 时间 | 事件 |
| --- | --- |
| 0 ms | 阶段容器已有最终尺寸，**不等待动效即可点击**「提交询价」；文字用 `from` 补间，不预留空位，因此没有 CLS |
| 0 – 1300 ms | `layer1` 从 `scale 1.1 / rotate -1.2°` 收到 `1 / 0`，同时全局柔光层淡入——这是「角度揭示」，模拟镜头从侧后方转到正面 |
| 200 ms | 高光层（`.hero__specular`）淡入，光标进入后才跟随 |
| 300 – 1900 ms | 文案行按 60–90 ms 递增上浮 12px + 透明度，标题最后落位（标题最长，读完需要时间） |
| 500 ms | 右侧仪表栏淡入 |
| 2200 ms | `--intro-done: 1`，此后指针/滚动接管 |

## 2. 指针（仅鼠标）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 旋转 | `rotationY ±2.6°`，`rotationX ±2.1°` | 2–3° 量级，超过就开始「晃」 |
| 位移 | `x ±10px`，`y ±8px` | 比旋转更小的位移，避免文字与图像相对滑动 |
| 缓动 | `gsap.quickTo(..., duration 0.8–0.9, power3.out)` | 单实例复用，不在每帧新建补间 |
| 帧控 | 一个 rAF，`raf=0` 前置判断 | 一帧最多一次写入 |
| 高光 | `--mx/--my` 写进 420px 径向渐变，`soft-light` 混合，`opacity 0.9` | 只在鼠标进入后出现；离开归零 |
| 页面 | **不位移** | 指针只影响媒体层与标题渐变，不影响布局容器 |

触屏（`pointerType !== "mouse"`）直接忽略，不注册任何效果。

## 3. 标题局部渐变

`--mx/--my` 默认 `130% / -30%`（即默认态几乎全为墨色）。鼠标进入标题区域后，用独立 rAF 更新这两个变量，渐变停靠点为「石墨 → 钢灰 → 钢蓝」，过渡 260 ms，`background-clip: text`，**文字仍可选中**（没有用伪元素遮挡），也没有布局位移。

React Bits 的 `gradient-text` 只在 hover 时按容器中心算角度，属于悬停态效果；本项目要的是「跟随指针位置的局部渐变」，所以自行实现，并在 `docs/references.md` 里写清了这个区别。

## 4. 滚动（桌面 190vh / 移动 120vh）

ScrollTrigger 配置：`pin: stage`、`scrub: 0.7`、`end: "+=190%"`（桌面）/ `"+=120%"`（移动，`gsap.matchMedia` 切换）。
**被 pin 的是容器，动画全部作用在 `layer1..3` 子元素上**——这正是 ScrollTrigger 文档要求的写法，否则 pin 的测量会漂移。

时间轴（以滚动进度计）：

| 进度 | 动作 |
| --- | --- |
| 0 – 30% | `layer1` 放大到 1.28 并轻微右移、透明度降到 0.15；文字组上移并淡出到 0.25（不消失，保持可读底线） |
| 22 – 55% | `layer2`（微距）从 1.15 收到 1.0，透明度 0→1；形成「推近引脚」的错觉 |
| 50 – 85% | `layer2` 淡出，`layer3`（俯视）从 1.1 收到 1.0 并淡入 |
| 全段 | `onUpdate` 按进度切 `.hero__state[data-active]`、说明文字、右侧读数 `0X / 03` |

快速滚动与反向滚动：因为全部是 `scrub` 驱动的补间（没有 `toggleActions` 的一次性回调），反向滚动会自然回放；导航跳转直接落到目标锚点，ScrollTrigger 由 `refresh()` 重新计算。
移动端 `end` 缩短到 120vh，避免小屏上「滚很久画面才动」。

## 5. 其它微动效

| 元素 | 效果 | 约束 |
| --- | --- | --- |
| 主/次按钮 | 磁性位移 3–5px（`MagneticButton`），箭头 `translateX(4px)` | 只响应鼠标；键盘聚焦时不位移；命中区域尺寸不变；`:focus-visible` 有 2px 描边 |
| 品牌格 | hover/聚焦时标识由墨色变为品牌色，`询价 →` 浮现 | 不依赖自动轮播；键盘 Tab 可遍历全部品牌 |
| 流程线 | `--progress` 随滚动增长，节点逐个点亮 | 细线 1px，不用发光 |
| 仓储图 | `clip-path` 揭开 + `yPercent -5→5` | 揭开只在进入视口时一次 |
| 数字/等宽标签 | 无计数动画（避免「数字滚动」的廉价感） | 读写都保持静态可读 |

## 6. 降低动效（`prefers-reduced-motion: reduce`）

- 入场补间全部跳过，直接呈现状态 01 的稳定首帧（文字、按钮、仪表栏都在最终位置）。
- 不创建 ScrollTrigger：hero 高度退回 100vh，后面内容紧接其后，**没有一个空白的 pin 占位**。
- 指针视差、标题渐变跟随、磁性按钮全部关闭。
- 媒体层保留静态柔光，不使用 `filter` 动画。
- 业务功能（导航、询价、语言切换、表单）与完整版**完全一致**——这条在 `scripts/shoot.mjs` 里以 `reducedMotion: "reduce"` 重新加载页面做过字形与溢出检查。

## 7. 已知不足

1. 三张图是生成图，微距帧的光学景深与真实微距有差距，换上真实摄影后 `scale` 区间可能要重调（当前 1.10–1.28 是按现有图的构图留白定的）。
2. 状态 02→03 之间在极快滚动（一次滚轮跨 2000px 以上）时能看到约 1 帧的双层叠影，属 `scrub` 追上过程的正常表现，未做额外遮罩。
3. 移动端 `end: 120%` 只有两次状态切换，第三状态在窄屏上基本一闪而过——这是刻意取舍（小屏长距离 pin 更烦人）。
